[`@btst/better-auth-ui`](https://github.com/better-stack-ai/better-auth-ui)
is the separately maintained Better Auth UI plugin package for BTST v4. It adds
resolved auth, account, organization, and admin routes while Better Auth UI continues to read its own
session and native permissions from your Better Auth client.

<Callout type="warn">
  This integration assumes your application already owns a Better Auth server
  endpoint. It does not generate a Better Auth backend, database adapter,
  schema, migrations, authentication providers, secrets, or deployment
  configuration.
</Callout>

## Generate the minimal integration

Select the companion explicitly; it is never part of the default scaffold.

```bash
npx @btst/codegen init --plugins better-auth-ui
```

The generated result:

- registers only `authClientPlugin()` and `accountClientPlugin()`;
- creates one browser client for the existing `/api/auth` endpoint;
- mounts routes under the resolved BTST site path (`/pages/auth/*` and
  `/pages/account/*` by default);
- configures API, site, and QueryClient runtime only once in
  `createClientStack()`; and
- refreshes the framework explicitly after a Better Auth session change.

Organization, admin, API-key, passkey, multi-session, billing, and other Better
Auth extensions remain opt-in. Configure the matching Better Auth server and
client plugins before enabling their UI. The default generated scaffold remains
auth and account only.

For a manual installation, add the companion and exact auth cohort alongside
your existing BTST dependencies:

```bash
pnpm add --save-exact @btst/better-auth-ui@3.0.0 \
  better-auth@1.7.6 @better-auth/core@1.7.6 \
  @better-auth/api-key@1.7.6 @better-auth/passkey@1.7.6 \
  @better-auth/utils@0.4.2 @better-fetch/fetch@1.3.2 better-call@1.4.0
```

API-key and passkey packages provide upstream type declarations; installing
them does not enable their server or client features. Component dependencies
are included in the companion package. Resolve remaining peer requirements
against its published manifest. The direct cohort above must remain aligned.
Upstream agent-auth and better-call also install their own supported versions
of `better-call` and `@better-auth/utils`; those nested implementation dependencies
can coexist and should not be forced to the application's direct versions.

## Browser client and resolved routes

The CLI generates the following application-owned seam:

```ts title="lib/auth-client.ts"
import { createAuthClient } from "better-auth/react"

export function createAppAuthClient(baseURL?: string) {
  return createAuthClient({
    ...(baseURL ? { baseURL } : {}),
    basePath: "/api/auth",
  })
}
```

Change `basePath` only when your existing Better Auth handler uses a different
path. The companion route bases are not configured here: they derive from the
site runtime passed once to `createClientStack()`.

```tsx title="lib/stack-client.tsx"
import { accountClientPlugin, authClientPlugin } from "@btst/better-auth-ui/client"
import { createClientStack } from "@btst/stack/client"

return createClientStack({
  api: { baseURL: apiOrigin, basePath: "/api/data" },
  site: { baseURL: siteOrigin, basePath: "/pages" },
  queryClient,
  plugins: {
    auth: authClientPlugin(),
    account: accountClientPlugin(),
  },
})
```

## Provider overrides

The resolved stack infers plugin override keys. Configure the Better Auth client
and upstream feature plugins once under `auth`. Account routes do not require
an `account: true` flag.

```tsx
<StackProvider
  stack={browserStack}
  router={frameworkRouter}
  overrides={{
    auth: {
      authClient,
      redirectTo: "/pages/account/account",
      onSessionChange: refreshThroughTheFramework,
    },
  }}
>
  {children}
</StackProvider>
```

Use the framework-native synchronization generated for your target:

<Tabs groupId="framework" items={["Next.js", "React Router", "TanStack Start"]}>

The bridge performs no hidden BTST identity refetch. If business plugins use
BTST authorization, map the Better Auth session separately with BTST's generic
`createClientAuth` and `createServerAuth` contracts and keep server
authorization authoritative.

## Optional feature families

The package includes upstream auth methods (phone, wallet, device, and agent
authorization), admin pages, organization management, audit logs, SSO, OAuth
client management and consent, and billing. Register `organizationClientPlugin()`
or `adminClientPlugin()` in the BTST client stack when those route families are
needed. Enable their upstream UI feature plugins through `overrides.auth.plugins`.
Only configured views render; disabled feature routes do not request feature data.

BTST supplies the components, pages, routing, notifications, localization, and
shared query client. Applications configure the matching Better Auth backend
plugins, external providers and credentials, and authorization rules. In
particular, an admin page does not grant admin access; the Better Auth backend
continues to enforce permissions.

## Migrating from companion v2

- Update the complete dependency cohort above, including React and Tailwind.
- Keep the `authClientPlugin()`, `accountClientPlugin()`, and
  `organizationClientPlugin()` registration pattern.
- Move flat feature flags into upstream UI plugins in `overrides.auth.plugins`.
- Remove `account: true` from provider overrides.
- Update account settings links from `/pages/account/settings` to
  `/pages/account/account` (adjust `/pages` for the configured site mount).
- Use upstream `Auth`, `Settings`, `Organization`, and `Admin` components
  when embedding UI directly. See the companion repository's migration guide
  for feature-specific configuration and removed component names.
