The 6.2 release includes the changes since Core 6.0.0. Install the exact package versions
below together. Stable packages use npm's `latest` channel.

```bash
pnpm dlx @btst/codegen@6.2.2 init
```

For an existing application, update only its selected packages and required code
dependencies. Keep runtime registration keys unchanged. The optional Better Auth
UI companion is `@btst/better-auth-ui@3.0.3`; database adapters remain `3.0.1`.

The [CLI installation set](https://github.com/better-stack-ai/better-stack/blob/main/packages/cli/src/utils/installation-set.ts)
records individual pins. Use this set with Core `>=6.2.2 <6.3.0`;
prerelease packages retain their separate beta compatibility ranges.

Core/codegen `6.2.2`, Blog `1.1.2`, CMS `1.2.1`, and Search `1.1.0` ship together.
Search adds exact-name and alias ranking, accessible dialog recovery, phrase
highlighting, and presentation callbacks. Blog bounds search fetching and
pagination. CMS reduces reverse-relationship round trips and scheduled-body
transfer. Core includes the updated ejectable Search registry; codegen installs
these exact versions.

For existing SQL applications, generate and review additive indexes on Blog
`post(published, createdAt)` and CMS
`contentRelation(targetId, fieldName, sourceId)` / `(sourceId, fieldName)`.
Apply the ORM migration separately; installing packages does not create indexes.
Preserve application-owned models and existing valid source/target relation
names when reviewing generated Prisma changes. The separate
[Prisma relation-generation defect](https://github.com/better-stack-ai/better-auth/issues/54)
is unchanged. Other plugin and adapter versions remain as listed above.

Core `6.2.1` and Blog `1.1.1` fix native Blog static rendering: prefetched list,
article, and tag content remains visible before JavaScript runs. Use the
[direct page entries](/plugins/blog#rendering-prefetched-pages) with hydrated
route data. Keep prefetched published content outside page-wide Suspense
boundaries. This rendering patch requires no schema migration.

### Required peers for an existing Next.js application

For Blog, CMS, and Search, install `@btst/stack@6.2.2`,
`@btst/plugin-blog@1.1.2`, `@btst/plugin-cms@1.2.1`, and
`@btst/plugin-search@1.1.0`. Their shared peers include `@btst/yar>=1.3.2`,
`@tanstack/react-query@^5`, and matching `react` / `react-dom` versions
`>=19.2.6`. Core also requires `better-call@1.4.4`,
`react-error-boundary>=4`, `sonner>=2`, and `zod>=4.2.0`; Next.js must be `>=15`.
The CLI pins React Query and Query Core together at `5.105.0`.

Keep the selected adapter and ORM peers too. Prisma uses
`@btst/adapter-prisma@3.0.1`; retain the application's compatible Prisma CLI,
client generator, and driver adapter. If selected, the Auth companion uses
Better Auth / `@better-auth/core@1.7.14` and `@better-auth/utils@0.5.1`;
AI Chat uses `ai@7.0.155`, `@ai-sdk/react@4.0.159`, and
`@ai-sdk/openai@4.0.104` in the scaffold.
Other model providers have their own SDK compatibility requirements.
`@btst/components@1.0.1` is optional; its form peers are
`react-hook-form@^7.66.1`, `zod@^4.6.7`, and `tailwindcss>=4` in addition to
React / React DOM. Use the
[installer's selected extras](https://github.com/better-stack-ai/better-stack/blob/main/packages/cli/src/utils/constants.ts)
and each package's peer dependencies rather than installing every optional plugin.
Commit the resolved lockfile. See the [existing-app workflow](/existing-app-v6)
for schema preservation and verification.

## Changes since 6.0

- [Blog](/plugins/blog) adds revision history, editorial review, scheduling, and page-specific cards. [CMS](/plugins/cms) adds publication policies, scheduled dispatch, and revision history.
- [Feedback](/plugins/feedback), [Helpdesk](/plugins/helpdesk), [Notifications](/plugins/notifications), and [Search](/plugins/search) add independent packages with application-owned authorization. Optional bridges connect notifications, support tickets, CRM contacts, and Kanban work.
- [Calendar](/plugins/calendar) adds provider synchronization, team assignment, group capacity, and waitlists. [School](/plugins/school) uses the shared asynchronous payment contract and connects course discussions.
- [Ecommerce](/plugins/ecommerce) adds digital delivery, protected downloads, authorized refunds, and recovery after uncertain provider responses. [Affiliate](/plugins/affiliate) supports shared payment attribution.
- [CRM](/plugins/crm) adds duplicate review and transactional merges, deal ownership, and owner filters. [Newsletter](/plugins/newsletter) adds campaign recovery and forms integration.
- [Analytics](/plugins/analytics) adds funnels and experiment conversion attribution; [Feature Flags](/plugins/feature-flags) exposes experiment reporting.
- [Form Builder](/plugins/form-builder) adds conditional fields, file uploads, and shared server validation. [Page component slots](/page-overrides) and route-scoped AI authoring context extend existing plugin pages.

## Upgrade persistent databases first

Generate the schema from the application's registered backend stack, review the
SQL, and apply additive migrations **before building pages that read the database**,
as well as before serving the upgraded packages. Installing packages or running
`prisma generate` does not migrate an application database. Blog reads can touch
`editorialActivation` during `generateStaticParams` or page-data collection even
when the application has not enabled editorial review. A missing table can fail
the build with Prisma `P2021`.

An isolated CI database being migrated does not prepare a Vercel preview's
database. Provision an isolated preview database and migrate it before its build.
If preview and production share a database, apply reviewed, backward-compatible
migrations once through a controlled release job before either build uses the new
schema. Do not add an unconditional production migration to every preview build.
See [schema generation and environment ordering](/existing-app-v6#preserve-the-application-schema).

| Selected feature | Required upgrade review |
| --- | --- |
| Blog | Add revision and editorial workflow models and fields. Follow the [revision migration](/plugins/blog#schema-migration-baselines-and-retention) before enabling history or review. |
| CMS | Add publication fields and revision models; review existing records before enabling a publication policy. |
| CRM | Add normalization and revision fields, backfill populated tables, and verify isolated transactions and foreign keys before enabling duplicate merges. Deal ownership reuses Kanban assignees. |
| School | Apply nullable enrollment payment-state columns and migrate synchronous payment callbacks to the shared asynchronous provider contract. |
| Calendar | Apply provider, team, capacity, waitlist, and payment-hold schema additions before serving the updated endpoints. |
| Ecommerce | Apply tax, verified-payment, digital-grant, and refund-attempt schema changes. Existing paid orders do not automatically become verified digital purchases. |
| New plugins | Generate the selected plugin's tables and configure its identity, permissions, storage, and delivery providers before exposing routes. |

Provider credentials, protected file storage, scheduled dispatch, email delivery,
and payment webhooks remain application responsibilities. Follow each selected
plugin's configuration guide. Keep the previous application artifact and lockfile
available while checking sign-in, public content, administrative writes, and any
enabled payment or background-dispatch flows.
